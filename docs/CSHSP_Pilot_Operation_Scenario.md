# CSHSP 직원 파일럿 운영 시나리오 (Sprint H)

> 대상: 건강검진센터 직원 파일럿 (내부 검토용). 기간·인원은 센터장 승인으로 확정.

## 1. 파일럿 개요

| 항목 | 내용 |
|------|------|
| 기간(안) | 2주 (1주차: 직원 내부 / 2주차: 제한된 실수검자 병행 검토) |
| 참여자 | 검진센터 직원 2~3명(승인·문진검토), 콜센터 1명(상담), 전산 1명(운영) |
| 범위 | 종합검진 예약 신청~승인~문진, AI 채팅 안내. **결제·검진결과는 범위 외** |
| 데이터 | 1주차 더미 / 2주차 전환 시 개인정보 책임자 검토 후 실데이터 |
| 알림 | Mock (PENDING 큐 확인까지) — 실발송 미연동 상태로 시작 |

## 2. 역할별 시나리오

### 시나리오 A — 수검자(직원이 역할 수행): AI 채팅 예약
1. `chat/` 접속 → 퀵버튼 "프로그램 추천" → 안내 확인
2. "7월 O일 오전 O시에 스마트로 예약하고 싶어요" 자연어 입력
3. 본인확인 폼(이름+전화 → 인증번호 123456) 완료
4. 예약 신청 → **"직원 확인 후 확정" 안내 문구 확인** (즉시 확정 안 됨을 체크)
5. "내 예약 확인해줘" → 본인 예약만, 인증 단계별 마스킹 확인
6. (검증 항목) 의료질문 1회 입력 → 차단·의료진 상담 안내 확인

### 시나리오 B — 검진센터 직원: 승인·운영
1. `admin/?mode=live` 접속 (본인 계정 선택)
2. 사이드바 "예약 승인 대기" → 신청 건 검토 → 승인 또는 거절(사유 입력)
3. Dashboard에서 KPI(승인 대기·확정) 변화 확인
4. Slot 관리: HOLD 잔존 건 해제, 필요 시 Slot 생성 요청
5. 일과 후: 알림 큐(PENDING→워커 실행 결과) 확인

### 시나리오 C — 문진 검토 (간호 담당)
1. 수검자 역할이 채팅에서 "사전 문진" 진행·제출
2. `admin/questionnaire_review.html` → SUBMITTED 목록 → 응답 검토
3. REVIEWED(확인) 또는 REJECTED(보완 요청 + 메모) 처리

### 시나리오 D — 콜센터: 상담 연계
1. 채팅에서 "상담원 연결" 요청 발생 → crm.json OPEN 건 확인
2. 처리 후 상태 변경(수동) — 파일럿 피드백으로 화면 필요성 평가

### 시나리오 E — 전산: 일일 운영
- 아침: health(8600)·정적(4000) 확인, 백업 성공 확인
- 저녁: `notification_worker.py` 실행 결과, AI 상담 통계(차단 유형) 확인
- 장애 시: Failure_Response_Manual 절차 수행

## 3. 성공 기준 (파일럿 종료 판정)

| 지표 | 목표 |
|------|------|
| 예약 신청→승인 처리 소요 | 평균 4시간 이내 (근무시간 기준) |
| AI 채팅 예약 신청 성공률 (정보 완비 시) | 90% 이상 |
| AI 오동작(확정 표현·의료 판단 노출) | **0건 — 1건이라도 발생 시 즉시 중단·보고** |
| 개인정보 노출 사고 | 0건 |
| 데이터 무결성(validator) | 일일 0오류 |
| 직원 만족(5점) | 3.5 이상 + 개선 요구 목록 확보 |

## 4. 피드백 수집
- 일일 10분 스탠드업 (막힌 화면·문구·오류 기록)
- 주간: AI 상담 통계 리뷰 → Safety 차단 유형별 오탐/미탐 분류 → 룰 보완 요청
- 종료 시: 정식 오픈 전 필수 보완 목록(실인증·실발송·계정 관리) 확정

## 5. 중단 기준 (Rollback)
- AI가 확정/의료판단 표현을 노출한 경우
- 개인정보가 미인증 세션에 노출된 경우
- 데이터 파손(validator 오류) 복구 실패 시
→ 채팅 위젯만 우선 차단(정적 서버에서 chat/ 제거)하고 admin·엔진은 유지 가능 (구조 분리 확인됨)
